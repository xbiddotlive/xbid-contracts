# Robinhood Testnet deployments

`timelock.json` is generated first by `DeployRobinhoodTimelock.s.sol`, then finalized from the confirmed broadcast receipt by `finalize-robinhood-timelock-manifest.sh`. It records the self-administered 5-minute Testnet Timelock, its locked Safe role matrix, actual deployment transaction hash, actual deployment block, and the separate simulation block. The Timelock at `0xDD935c94d8433CF959d12Dd915bb3Cd0a245876B` is publicly source-verified on Robinhood Testnet Blockscout. `latest.json` was generated by `DeployRobinhoodTestnet.s.sol` during the successful Phase A broadcast; it is the machine-readable source of protocol addresses, runtime code hashes, roles, versions, a conservative simulation scan start block, and governance activation calldata. `phase-a-receipts.json` records the independently re-read transaction receipts, the receipt-backed Indexer start block, and the verified inactive state.

Rules:

- Never hand-edit a generated manifest.
- Review each manifest against its schema and read-only validator before continuing.
- Commit the reviewed manifest so frontend, backend, indexer, and operations use one address source.
- A manifest contains no private key, mnemonic, RPC credential, or Safe signature.
- `status` records the safe state produced by the deployment transaction and remains `PENDING_GOVERNANCE_ACTIVATION`. Current activation is derived from on-chain state by the validator; never rewrite history in this file.
